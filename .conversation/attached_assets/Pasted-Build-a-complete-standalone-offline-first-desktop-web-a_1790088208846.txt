Build a complete, standalone, offline-first desktop web application called “Field Restore.”

Purpose:
Create a focused audio-restoration editor for my own mono, stereo, and binaural field recordings. It should cover practical field-recording cleanup and editing only:

- Gain
- Fades
- EQ
- DC-offset analysis and removal
- Static, dynamic, and adaptive hum removal
- Occasional wind and low-frequency rumble control
- Waveform selections and named regions
- Local attenuation or muting
- Manual ambient patch replacement using nearby material from the same recording
- Waveform statistics and audio analysis
- Reliable WAV rendering and export
- Restoration reports and repeatable project documentation

Do not turn this into a DAW, music-production environment, AI music generator, cloud service, sample library, collaboration app, multitrack editor, generic podcast tool, or online audio editor.

The application should feel like a serious, restrained field-recording restoration utility: clear, local, reversible, technically honest, and reliable.

Primary principles:
- Original imported audio must never be changed.
- All edits must be non-destructive until the user explicitly exports a rendered WAV.
- Process all audio locally in the browser.
- Preserve mono/stereo structure by default.
- Preserve binaural stereo timing and channel relationships.
- Do not claim to duplicate or replace commercial spectral-repair algorithms.
- Do not make false AI, machine-learning, “perfect restoration,” or “artifact-free” claims.
- Favor conservative restoration controls, precise manual selection, preview, comparison, undo, and transparent reporting.

Platform and privacy requirements:
- Build as a local-first, offline-capable Progressive Web App.
- The application must work without a login, user account, cloud database, server-side processing, analytics, telemetry, subscriptions, paid APIs, or audio upload.
- All analysis, rendering, playback, statistics, and WAV export must occur locally in the browser.
- Use IndexedDB for local projects, presets, settings, statistics cache, edit history, and metadata.
- Use the File System Access API when supported for opening and saving files.
- Provide standard browser download/upload fallback behavior for browsers that do not support File System Access API.
- Optimize for Windows 11 in Chrome and Edge.
- Keep dependencies free and open source.
- Do not require Electron, FFmpeg, Node-based server processing, a backend, or external services for version 1.
- Use accessible controls, keyboard navigation, visible focus states, readable labels, tooltips, validation, and useful error messages.
- Build a working application, not a UI mock-up, wireframe, or non-functional demo.
